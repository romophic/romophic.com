30秒でわかる全体像

  • 完全な静的サイト。 記事も一覧もOG画像も、すべて pnpm build の時点でファイルになる。
  • コンテンツの正はMarkdown / MDX。 Astro Content Collectionsが型と親子関係を管理する。
  • 重い処理はビルド時。 目次、バックリンク、読了時間、RSS、グラフ用JSON、検索インデックスを事前計算する。
  • ブラウザで動くのはUIだけ。 テーマ、検索、グラフ、コメント、目次の追従など。
  • DB・APIサーバー・CMSはない。 dist を静的ホストに置けば完結する。
01 / Orientation

まずは「何がどこで動くか」

このサイトを理解する最短ルートは、ビルド時に決まるものと、ブラウザで初めて動くものを分けて考えること。

Build time

ビルド時に確定する

  • 全ページのHTMLとCSS
  • 記事の並び順、親子関係、タグ
  • 目次、バックリンク、読了時間
  • RSS、llms.txt、sitemap、robots.txt
  • OG画像、グラフ用 /graph.json
  • Pagefindの検索インデックス
Client time

ブラウザで動く

  • テーマの復元・切り替え
  • 検索UIの読み込みと検索
  • D3グラフの物理演算と描画
  • Giscusコメントの埋め込み
  • 目次の現在位置、スクロールUI
  • View Transitionsによる画面遷移

つまり: 表示内容のほぼすべては静的HTMLとして配信される。JavaScriptが失敗しても、記事本文・一覧・タグ・RSSは読める。検索・グラフ・コメント・テーマ切替が「強化機能」として乗っている構成。

02 / Architecture

アーキテクチャ

ソースから本番までの一本道。左から右へ流れ、途中で派生ファイルが生まれる。

1 src/content Markdown / MDX、著者、プロジェクト
→
2 Astro Collection取得、ページ生成、データ集約
→
3 派生ファイル Pagefind / RSS / OG / graph.json
→
4 dist HTML・CSS・JS・画像・XML・TXT
→
5 静的ホスト そのまま配信。実行時サーバー不要
項目現在の値補足
サイト名romophicsrc/consts.ts の SITE.title
本番URLhttps://romophic.comAstroの site と SITE.href の両方に設定
言語ja-JPHTMLの lang="ja"、OG localeは ja_JP
出力静的HTMLSSRアダプターなし。DB・APIなし
パッケージ管理pnpm 10.24.0packageManager で固定
Node>= 22.22.0engines で指定
ビルドastro check && astro build型チェックが通らないとビルドできない
公開物dist/50 HTML、391ファイル、約25.8MB

ページ生成の考え方

  • getStaticPaths() で公開記事・タグ・OG画像のURLを列挙する。
  • 各ページは src/pages の薄いルートファイルから、src/components の表示コンポーネントへ渡す。
  • データ取得は src/lib/content に集約し、ページ側でCollectionを直接触らない。
  • 一覧・記事・タグ・RSS・グラフで同じ正規化済みIDを使う。

設計原則

Native first

Astro標準機能を優先

Content Collections、reference()、getStaticPaths()、Image、View Transitionsをそのまま使う。

Build first

実行時処理を減らす

目次・バックリンク・読了時間・検索インデックスをビルド時に確定。クライアントは表示に専念する。

Small runtime

必要なJSだけ

検索は初回オープン時、グラフはidle時。React等のUIランタイムは読み込まない。

補足: プロジェクト紹介のタグにはReactやNuxtが含まれるが、このサイト自体のUIランタイムはAstro + 素のJavaScript。Reactは使っていない。

05 / Content model

コンテンツモデル

3つのCollectionで、記事・著者・プロジェクトを型安全に管理する。ファイルを置けばページが増える仕組み。

Collection場所件数用途
blogsrc/content/blog/**/*.{md,mdx}37公開 + 1下書き + 1テンプレート記事、親記事、サブ記事
authorssrc/content/authors/*.{md,mdx}1記事の著者情報
projectssrc/content/projects/*.{md,mdx}3Aboutに表示する制作物

blog のfrontmatter

フィールド必須型・意味
title必須記事タイトル。見出し・OG・RSS・検索に使う
description必須一覧・meta description・OG・RSS用の要約
date必須公開日。文字列はDateに変換される
parent任意親記事への reference('blog')
order任意サブ記事の並び順。未指定は0
image任意カバー画像。Astroの画像メタデータとして解決
tags任意文字列配列。タグページとグラフに使う
authors任意著者への参照配列
draft任意既定は false。true なら公開しない
updatedDate任意更新日。RSSの atom:updated とJSON-LDに使う

IDの正規化

AstroのCollection IDは、フォルダ内の index.mdx だと slug/index になる。このサイトでは normalizePostId() が末尾の /index を落とし、全消費側で同じIDを使う。

src/content/blog/joined-howtv/index.mdx
  → raw ID: joined-howtv/index
  → normalized ID: joined-howtv

src/content/blog/romophic-library/lib/union-find.mdx
  → raw ID: romophic-library/lib/union-find
  → normalized ID: romophic-library/lib/union-find

親記事とサブ記事

親子関係は2通りで判定する。明示的な parent が最優先。なければIDのスラッシュ区切りから親を推測する。

romophic-library                  ← 親記事
├── lib/union-find                ← サブ記事
├── lib/segment-tree              ← サブ記事
├── lib/dijkstra                  ← サブ記事
└── ...                           ← 全31本

サブ記事の並び順

order 昇順 → date 昇順 → ID順。ナビゲーションと目次はこの順序に従う。

記事の並び順

全記事は date 降順 → ID順。ブログ一覧、RSS、最新記事、llms.txtが同じ順序を使う。

下書き: draft: true の記事は getAllPosts() から除外され、ページ・RSS・グラフ・関連記事のどこにも出ない。親記事が下書きの場合も、参照解決時に下書き親は返さない。

サブ記事のfrontmatter例

---
title: Union-Find
description: 素集合データ構造の実装メモ
date: 2026-01-15
parent: romophic-library
order: 10
tags:
  - c++
  - competitive programming
authors:
  - romophic
draft: false
---

著者とプロジェクト

authors

1人の著者

name、avatar、bio、website、github、mail など。記事側からは authors: [romophic] で参照する。

projects

3つの制作物

name、description、tags、image、link、startDate、endDate。Aboutで開始日の新しい順に表示する。

06 / Pipeline

コンテンツがHTMLになるまで

MDXの1ファイルが、本文・目次・メタデータ・フィード・検索対象へ展開される流れ。

  1. Collection取得。 getCollection('blog') で下書きを除外し、IDを正規化。ビルド中はモジュールキャッシュに載る。
  2. 派生データの計算。 親子、前後記事、タグ、読了時間、目次、バックリンクを getPostPageData() が並列で集約する。
  3. Markdown / MDX変換。 remarkで数式と絵文字、rehypeで見出しID・autolink・外部リンク・KaTeXを処理する。
  4. コードブロック。 Expressive Codeがlight/darkテーマ、行番号、折りたたみを付ける。
  5. 画像。 Markdownの画像は MdxImageCaption にマッピングされ、400 / 800 / 1200pxのresponsive imageになる。
  6. ページ描画。 BlogPost.astro がヘッダー、目次、本文、バックリンク、コメント、前後ナビを組み立てる。
  7. 派生エンドポイント。 RSS、llms、graph.json、OG画像、sitemapを別ルートで生成する。
  8. 検索インデックス。 Pagefindが data-pagefind-body の付いた記事本文だけをインデックス化する。

Markdown拡張の設定

処理ライブラリ効果
数式remark-math + rehype-katex$...$ と $$...$$ をKaTeXで描画
絵文字remark-emoji:smile: などを絵文字に変換
見出しIDrehypeHeadingIdsTOCとアンカーの基礎になるslug
見出しリンクrehype-autolink-headings見出しの前に # リンクを付与
外部リンクrehype-external-linkstarget="_blank"、rel="nofollow noreferrer noopener"
コードExpressive Codelight/dark、行番号、折りたたみ、コピーUI

数式の扱い

記事本文に数式があるか hasMathContent() で判定し、数式があるページだけKaTeXのCSSをインライン展開する。数式のない記事にKaTeX CSSを載せない。

現在の状態: katex パッケージと rehype-katex が内部で使うレンダラーはともに 0.16.47。CSSと生成HTMLのバージョンは揃っている。

読了時間

空白を除いた本文の文字数を400で割り、切り上げ。最低1分。親記事には「自分の本文 + 全サブ記事」の合計も表示する。

minutes = max(1, ceil(文字数 / 400))

バックリンク

本文中のMarkdownリンクを正規表現で抽出し、コードブロックとインラインコードを除外。リンク先を記事IDに解決し、双方向の参照マップをビルド中に1回だけ作る。画像リンクは対象外。

解決できるリンク

  • /blog/romophic-library
  • ./other-post
  • ../parent/lib/foo
  • クエリ・フラグメント付きURL

対象外

  • http(s):// の外部リンク
  • mailto:
  • コードブロック内の文字列
  • Markdown画像 ![alt](src)
07 / Pages

各ページの仕様

見た目だけでなく、どのデータを読み、何を表示するかまで。

ホーム /

構成

  • 固定背景の全面D3グラフ
  • ガラス調のダッシュボード
  • アバター、自己紹介、SNS、Aboutボタン
  • 365日のActivity Graph
  • 最新記事2件
  • 下部にグラフ操作エリア

挙動

  • 標準 Layout ではなく BaseLayout を使う
  • 通常はグラフの上にガラス面があり、ポインターはコンテンツ側
  • 最下部までスクロールするとグラフが操作可能になる
  • 「Back to Content」で先頭へ戻る
  • スクロール位置の自動復元は無効化
  • スキップリンクの対象は #main-content

ブログ一覧 /blog

  • 公開記事を年ごとに区切り、新しい年から表示する。
  • 1ページ20件。/blog/2 のようにページネーションする。
  • 各カードにタイトル、要約、著者、日付、読了時間、サブ記事数、タグを表示。
  • カード全体が記事へのリンク。タグはカード内の別リンクとして前面に出す。
  • 前ページ・次ページと「Page X of Y」を表示。

タグ /tags

  • 全タグを使用記事数の降順、同数なら名前順で表示。
  • 各タグに件数バッジを付ける。
  • タグ別一覧も同じ20件/ページのページネーション。
  • タグ名はURLにそのまま入る（例: /tags/competitive programming/）。

記事 /blog/[id]

上部

  • カバー画像（あれば）
  • タイトル、著者、日付、読了時間、サブ記事数
  • タグ
  • デスクトップ用TOCサイドバー
  • モバイル用TOCドロワー
  • サブ記事がある場合のサブ記事ナビ

本文以降

  • MDX本文
  • バックリンク（Linked References）
  • Giscusコメント
  • 前後記事ナビ（サブ記事は前後サブ記事 + 親記事）
  • Scroll to Topボタン
  • 数式があればKaTeX CSS

TOCの仕様

通常記事では自分の見出しだけ。サブ記事では「親記事のOverview」と「全サブ記事の見出し」をまとめたTOCになる。デスクトップは追従サイドバー、モバイルは <details> のドロワーで、現在の見出しをIntersectionObserverで強調する。

サブ記事ナビ

親記事と全サブ記事をリスト表示する。モバイルでは <details> を開いたとき、現在の記事が見える位置まで自動スクロールする。記事を選ぶとドロワーは閉じる。

About /about

  • Career、Education、Awardsの固定タイムライン。
  • Tech Stackは TECH_BADGES のキーをバッジ表示。
  • Connectは SOCIAL_LINKS を表示。
  • Projectsは projects Collectionを開始日降順で表示。

404

大きな「404」、説明文、ホームとブログへの2つの導線。meta robotsは noindex, nofollow。

共通レイアウト

要素仕様
Headerロゴ、home / blog / tags / about、検索ボタン、テーマ切替。現在地に aria-current="page"
Footerサイト名、コピーライト、GitHub / Email / RSS
ScrollProgress画面上端に読了率バー。記事以外の Layout でも表示
SkipLink先頭でTabすると「Skip to content」が出て #main-content へ移動
SearchDialog全ページ共通。BaseLayoutの末尾に1つだけ配置
LiquidGlassFilter対応ブラウザ向けの屈折SVGフィルター。非対応でも通常のblurで動く
08 / Search

検索

外部検索サービスなし。Pagefindの静的インデックスをブラウザで引く。

1ビルド記事本文をPagefindがインデックス化
→
2初回オープンUIのJS/CSSを初めて読み込む
→
3検索WASMでローカル検索
→
4遷移結果から記事へ移動

操作

  • ヘッダーの虫眼鏡、または Ctrl + K / Cmd + K
  • ネイティブの <dialog> を showModal() で開く
  • 背景クリックで閉じる
  • 開いた直後に検索inputへフォーカス
  • テーマに合わせて data-pf-theme を切り替え

実装の要点

  • Pagefind UIは初回オープンまで読み込まない
  • 10秒のタイムアウトと再試行を持つ
  • 読み込み中・失敗を role="status" で通知
  • インデックス対象は記事本文のみ（37ページ）
  • 一覧・タグ・Aboutは検索対象外

開発時: Pagefindの成果物は dist にしかない。開発サーバーで検索を試すには先に pnpm build が必要。UI側もその旨をエラーメッセージに出す。

09 / Graph

知識グラフ

記事・タグ・内部リンクの関係を、D3 force + Canvas + Web Workerで描く。

データの作り方

要素内容
ノード公開記事（id = post.id）とタグ（id = tag-<tag>）
記事→タグの辺frontmatterの tags から生成
記事→記事の辺本文中の内部リンクを extractInternalLinks() で抽出
重複クライアント側でノードIDを重複排除、逆方向リンクを双方向として扱う
次数・カテゴリリンク数からdegreeを計算し、タグ色を記事へ継承
配信/graph.json。現在約15.9KB

描画と操作

物理演算

  • D3 forceをWeb Workerで実行
  • linkDistance 60、charge -150
  • center / x / y の強さ 0.15
  • collide半径 15
  • タブ非表示中は停止
  • reduced motionでは回転を止める

操作

  • ホイールでズーム（0.1〜8倍）
  • 背景ドラッグでパン
  • ノードドラッグで位置変更
  • ホバーで隣接ノードを強調
  • クリックで記事またはタグへ遷移
  • ラベルはズーム時・重要ノードのみ

表示場所: 現在グラフを使うのはホームだけ。記事ページには埋め込んでいない。ホームではガラス面の背後で回転し、最下部で操作可能になる。初期化は requestIdleCallback まで遅らせ、LCPを邪魔しない。

11 / UI & a11y

テーマ、UI、アクセシビリティ

軽量な素のJSで、テーマ・フォーカス・モーション設定を扱う。

テーマ

決め方

  • localStorage.theme が最優先
  • なければOSの prefers-color-scheme
  • darkは <html class="dark"> で表現
  • 初期化スクリプトをheadで即実行し、FOUCを防ぐ
  • View Transitions前後でclassを引き継ぐ

色

  • Tailwind 4の @theme とCSS変数
  • 色はoklchで定義
  • 背景・文字・card・muted・border・ringなどをトークン化
  • 「Liquid Glass」はナビ、ヘッダー、モーダルに限定
  • ライト/ダークでOG画像は共通の暗色デザイン

アクセシビリティの実装

  • 全ページ共通のSkip Link。Tabで表示され、#main-content にフォーカス可能な状態で移動する。
  • Headerの現在地に aria-current="page"。
  • 検索はネイティブ <dialog>、状態通知は role="status" + aria-live="polite"。
  • モバイルTOC・サブ記事ナビはネイティブ <details>。
  • アイコンボタンには aria-label または sr-only テキスト。
  • フォーカスリングを focus-visible で表示。
  • prefers-reduced-motion でCSSアニメーションをほぼ無効化。
  • 画像には代替テキスト。Markdownのaltはキャプションにも使う。

現状の注意: 一部のJSスクロール（TOC追従、Scroll to Top、ホームの戻り）は明示的に smooth を指定しており、reduced motion設定でも滑らかに動く。CSSの scroll-behavior だけではJS指定を打ち消せない。

スクロールUI

  • ScrollProgress: ページ全体のスクロール率を上端のバーに表示。
  • ScrollToTop: 300px以上スクロールし、フッターが見えていないときだけ表示。フッターが見えたら隠す。
  • TOC: IntersectionObserverで現在の見出しを強調。モバイルは円形プログレス付き。
12 / Navigation

画面遷移とクライアント初期化

AstroのClientRouterで、ページ間をソフトナビゲーションする。

遷移

  • ClientRouter を全ページのheadに配置
  • リンクのhoverで先読み（prefetch.defaultStrategy: 'hover'）
  • 遷移時にDOMを差し替え、スクロール位置をリセット
  • テーマclassは astro:before-swap で新DOMへ引き継ぐ

再初期化

  • astro:page-load で検索、Giscus、TOC、グラフ、テーマボタンを再セットアップ
  • astro:before-swap でObserver・イベント・Workerを破棄
  • 二重登録を避けるため、ハンドラを都度差し替える

設計上のポイント: 通常の静的サイトのように「ページごとに全部JSを読み直す」のではなく、Astroのライフサイクルイベントに合わせて必要なものだけ再接続する。コメントとグラフは特に、URL・テーマ・DOMが確定した後に初期化する必要がある。

デプロイの前提

  • dist をそのまま配信できる静的ホストであればよい。Node.jsランタイムは不要。
  • site は https://romophic.com 固定。ドメインを変えるなら astro.config.ts と SITE.href の両方を更新する。
  • OG画像はビルド時に生成されるため、ホスト側でsatoriやresvgを動かす必要はない。
  • Pagefindもビルド時に生成される。デプロイ後に検索インデックスを作る工程はない。
  • 末尾スラッシュの正規化はホストの挙動に依存する。リダイレクト設定を変えるときは注意。

キャッシュ: OG画像とOG用フォントは node_modules/.cache に保存される。CIでキャッシュしない場合、初回ビルドは外部フォント取得に依存する。Interの取得に失敗するとOG生成は失敗する。

17 / Operations

記事・設定の変え方

日常的に触る場所と、壊しやすいポイントを実務目線で。

記事を追加する

  1. src/content/blog/ に .mdx または .md を置く。親記事は slug/index.mdx、単発記事は slug.mdx でもよい。
  2. 必須の title、description、date を書く。
  3. サブ記事なら parent: romophic-library と order を指定する。
  4. タグを付けるとタグページとグラフに反映される。
  5. pnpm build でページ、RSS、OG、検索インデックスが同時に更新される。

内部リンクのルール

記事間リンクは /blog/... の絶対パスで書く。相対リンクも解決できるが、URLの末尾スラッシュ仕様が揺れているため、絶対パスに統一するのが安全。

良い: [Union-Find](/blog/romophic-library/lib/union-find)
良い: [親記事](/blog/romophic-library)
避ける: [隣の記事](../other-post)

よく変える設定

変えたいもの場所
サイト名・説明・URL・著者・ページ件数src/consts.ts の SITE
ナビゲーションsrc/consts.ts の NAV_LINKS
SNS・RSSリンクsrc/consts.ts の SOCIAL_LINKS
Giscusのリポジトリ・カテゴリsrc/consts.ts の GISCUS_CONFIG
グラフの物理・色・操作src/consts.ts の GRAPH_CONFIG
サイトURL・フォント・prefetchastro.config.ts
Markdownの変換規則astro.config.ts の markdown.processor
記事のスキーマsrc/content.config.ts
カバレッジ閾値vitest.config.ts

プロジェクトを追加する

  1. src/content/projects/ にMarkdownを追加。
  2. name、description、tags、image、link を設定。
  3. startDate / endDate は任意。Aboutでは開始日降順。
  4. 画像は src/assets などのAstroが解決できる場所に置く。

著者を追加する

  1. src/content/authors/ にMarkdownを追加。
  2. name と avatar を設定。avatar は絶対URLか / 始まり。
  3. 記事側で authors: [ファイル名] と参照する。

公開前チェック: pnpm lint → pnpm test:coverage → pnpm build。ビルドが通れば、記事ページ・RSS・OG・Pagefind・sitemapまで一通り生成されている。

18 / Caveats

既知の注意点

「仕様」ではなく、2026-10-22時点の実装に残っている注意点。修正するときは関連箇所をまとめて直す。

項目現状影響
末尾スラッシュ trailingSlash 未設定。内部リンクはなし、canonical/sitemapはあり。 ホストの正規化次第でリダイレクトが増える。URL変更時は全リンク確認。
KaTeX CSS / レンダラーともに 0.16.47。 CSSと生成HTMLのバージョンは一致している。
検索の開発時挙動 Pagefind成果物は dist のみ。 pnpm dev だけでは検索できない。先にbuildが必要。
TOCの親見出し サブ記事で親見出しへのリンクが現在の記事IDにフォールバックする箇所がある。 親記事へ正しく飛ばないアンカーが生じ得る。
Activity Graph 365日分を描画するが、件数ラベルは全投稿数。日付データに不正値がある記事もある。 「last year」の件数と実際の期間が一致しない。
OGキャッシュ フォントを外部取得し、node_modules/.cache に保存。キャッシュキーはタイトル・日付・サイト名・version。 ネットワーク失敗でビルド失敗。デザインだけ変えてもキャッシュが残る場合がある。
RSS 全文HTML入りで約1.29MB。フラグメント付きリンクはそのまま。 フィードリーダーによっては重い。記事内アンカーは遷移先で解決が必要。
クライアントテスト ブラウザE2Eなし。インラインスクリプトはcoverage対象外。 検索・グラフ・コメントの実挙動は手動確認が必要。

考え方: これらは「設計の意図」ではなく「現在の実装状態」。修正する場合は、この仕様書の該当セクションも同時に更新する。

20 / Glossary

用語集

この文書とコードでよく出る言葉。

Content Collection

AstroがMarkdown/MDXを型付きで管理する仕組み。frontmatterの検証と参照解決を担当する。

親記事 / サブ記事

大きな記事を分割した構造。親が概要、サブが個別トピック。URLも /blog/parent/child になる。

正規化ID

末尾の /index を落とした記事ID。ページURL、グラフ、バックリンク、前後ナビで共通に使う。

バックリンク

ある記事を参照している他の記事。本文中の内部リンクからビルド時に自動計算する。

Pagefind

静的サイト向けの検索ライブラリ。ビルド時にインデックスを作り、ブラウザでWASM検索する。

Giscus

GitHub Discussionsをコメント欄として埋め込むサービス。サイト側にDBを持たない。

OG画像

SNSでURLを共有したときに出る1200×630の画像。Satoriで生成する。

View Transitions

AstroのClientRouterによるページ間のソフトナビゲーション。DOMを差し替え、JSを再初期化する。
