01 — DIAGNOSIS

現状診断：問題は 6 つのテーマに集約できる

個別のバグは症状。根は「同じことを複数の場所でやっている」こと。テーマ単位で直すと、修正が小さく・再発しにくくなる。

データの一貫性 5件

「同じはずの値」が場所によって違う。

  • ID の /index 除去が 4 箇所に重複し、OG ルートだけ漏れている
  • 日付整形がビルドマシンの TZ 依存（ActivityGraph は JST で 1 日ズレる）
  • getParentPost だけ draft フィルタを迂回
  • 内部リンク regex が画像 ![...](...) にもマッチ
  • 同時刻記事が大量にあり、並び順が不定

ライフサイクル 5件

「作って、殺していない」ものたち。

  • GraphViewManager の destroy() が誰からも呼ばれない（SPA 遷移ごとに worker + rAF + observer がリーク）
  • TOCHeader の scroll リスナーと observer が解放されない
  • グラフの worker がアイドル時も永久に回転・描画し続ける
  • リサイズが物理シミュレーションの中心に反映されない
  • velocityDecay は設定済みに見えて実は死んでいる

ユーザーに見える欠陥 7件

今すぐ直す「止血」対象。

  • デフォルト OG 画像 /static/1200x630.png が存在せず全ページ 404
  • 親記事 OG が生成側と消費側の述語不一致で 404（実測確認済み）
  • グラフのノードドラッグが d3-zoom に食われて完全に無効
  • タグノードのクリック先 /blog?tag= を誰も読んでいない
  • ブログ一覧に h1 なし・ul 直下に div・aria-current 誤り

重複 5件

変更コストと不一致の温床。

  • カードの 15 クラス文字列が BlogCard / ProjectCard / Backlinks にコピー
  • メタ行（著者・日付・読了・子記事数）が 3 ファイルに重複
  • 折りたたみ + 見出し追跡ロジックが 3 コンポーネントに重複
  • ソーシャルアイコン lookup が 4 箇所・fallback が 2 種混在
  • OG の親判定が 2 種類の定義で存在

死コード 約35箇所

読む人の推論コストを上げる残骸。

  • 未使用コンポーネント（Hero / SocialIcons / Badge テンプレート）
  • 未使用 API・フィールド・config（10 以上）
  • 死んだ CSS トークン（chart / popover / accordion / Radix 変数）
  • 死んだ設定（Vite external / Pagefind 二重索引 / components.json）
  • 読み込まれない Geist フォント定義と未使用 woff2

ガードレール 5件

「守る仕組み」自体の欠陥。

  • CI がテストを実行しない（pnpm test は watch モード）
  • 真空テスト（アサーション 0 件 / catch 内 assert / 自己参照）
  • README は Astro v6・remark プラグイン・zero-any を主張するが実態と乖離
  • クライアント動作（theme / 検索 / グラフ）は全く未テスト
  • AGENT.md の .spec.ts 指示は実在しない
一次検証で否定した指摘 — 「joined-howtv の日付が不正でビルド不能」は誤検知でした。 YAML パーサはこの表記を受理し、astro sync の成功を実行確認済み。正規化は推奨しますが緊急ではありません。 同様に「sharp は不要」「タグにサブポストを含む」は意図の可能性があるため、単独では変更しません。
02 — PRINCIPLES

設計原則：これが全判断の基準

迷ったらこの 5 つに戻る。個別の修正はすべてこれらの系として導出される。

1

唯一の真実 (Single Source of Truth)

ID 正規化・日付整形・親子判定・カードの見た目は、それぞれたった 1 箇所にだけ存在させる。 2 箇所にあった瞬間、それは未来のバグ（実際に OG 404 はこれで起きた）。

2

薄いページ、太い lib

src/pages は組み立てだけ。判断ロジックはすべて src/lib の純関数へ。 純関数はテストしやすく、グラフやコンポーネントからも再利用できる。

3

対称なライフサイクル

リスナー・worker・observer は「作った場所で必ず殺す」。astro:page-load には必ず astro:before-swap の対を用意する。これだけでリーク族のバグが構造的に消える。

4

削除が最優先

抽象化より先に死コードを消す。読む人の推論コストは最大の負債。 「grep で参照ゼロ」を証明してから削る。削除は機能追加より安全で、常に価値がある。

5

テストが仕様 (Test as Documentation)

テスト名に自然言語の意図を書く。空のアサーションや自己参照は「嘘の仕様書」なので許さない。 CI は lint + test + check + build の 4 段ゲートで、緑 = 仕様が守られている状態。

0

Vibe Loop で進める（既存方針）

各フェーズは「失敗するテストを先に書く → 最小の実装で直す → 緑を確認」のループ。 フェーズ完了の条件は常に CI 緑。これが進行の唯一の客観証拠になる。

03 — TARGET ARCHITECTURE

目標アーキテクチャ：5 層のまっすぐな流れ

大きな構造変更はしません。今の良い骨格（content → lib → components → pages）を保ち、各層の責務を 1 本の矢印で言えるようにする。

PAGES ルーティングと組み立てのみ
薄い層。getStaticPaths とコンポーネントへの受け渡しだけ。ロジック・整形・判定は書かない。
↓
COMPONENTS フラットな表示部品（SSR のみ）
階層は増やさない（現方針維持）。共有の見た目は @utility card と PostMeta に集約。クライアント script は「page-load と before-swap の対」を必須ルールに。
↓
LIB content クエリ / graph / utils — 純粋ロジック
テストで仕様を固定する層。dateKey / formatDate / isParentPost / pluralize など、判断はすべてここ。OG 生成・グラフ・ページは皆この関数を呼ぶ。
↓
CONTENT.CONFIG.TS schema + generateId（ID 正規化はここだけ）
入口で正規化する。/index 除去などの ID 処理はローダー設定 1 行に。lib から replace() が全部消える。
↓
CONTENT 執筆者だけの場所（Markdown / MDX / 画像）
唯一の源。コンテンツ変更でコードを触る必要がない状態を守る。
この図の読み方 — 上から下へ「依存は一方向」。逆流（components が日付を自前整形する、ページが ID を replace する）を見つけたら、それはリファクタリング対象のサイン。 Phase 1〜3 の作業は全部この図に収束させるためのもの。
04 — BEFORE / AFTER

主要な変化をコードで確認

抽象論ではなく、実際にこう変わるという 6 つの代表例。すべて現行コードの実物を基にしています。

A. ID 正規化を入口に一本化する Phase 1

4 箇所に散っていた /index 除去をローダーへ移動。OG 404 の根本治療。

BEFORE — 4箇所に重複・OGだけ漏れ

C. グラフのライフサイクルを対称にする Phase 0

作ったマネージャは必ず殺す。in-flight の fetch も中断。SPA 遷移 10 往復でも worker は増えない。

BEFORE — 作るだけ、殺さない

document.addEventListener('astro:page-load', () => {
  if (document.getElementById('graph-container')) {
    const initGraph = () =>
      new GraphViewManager('graph-container', 'graph-canvas')
    // インスタンスは誰も持たない
    // before-swap 処理なし
    // → worker / rAF / observer が
    //   遷移のたびに永久に残る
  }
})

AFTER — mount / unmount の対

import { GraphViewManager } from '@/lib/graph/manager'

let manager: GraphViewManager | null = null

const mount = () => {
  if (!document.getElementById('graph-container')) return
  manager?.destroy()
  manager = new GraphViewManager(
    'graph-container', 'graph-canvas',
  )
}

document.addEventListener('astro:page-load', mount)
document.addEventListener('astro:before-swap', () => {
  manager?.destroy()      // worker + observer + rAF を解放
  manager = null
})

// 併せて manager 内部に destroyed フラグを追加し
// fetch 中断 → init 復活を防ぐ

05 — EXECUTION

実行フェーズ：止血 → 一本化 → 深化 → 研磨 → 門番

各フェーズは独立してマージ可能。フェーズ完了条件は常に「CI 緑」。小さい PR を積み重ねる。

PHASE 0 ✓
止血
壊れている 7 件を直す。挙動の変更なし、修正のみ。
PHASE 1 ✓
芯の一本化
ID・日付・親判定・リンク解析を lib に集約。
PHASE 2 ✓
ライフサイクル
グラフと TOC のリーク根絶、worker 制御、描画最適化。
PHASE 3 ✓
研磨
重複排除・死コード削除・a11y パック・分割。
PHASE 4 ✓
門番
テスト品質修復・ドキュメント実態合わせ・CI 強化。

PHASE 0 止血 — 壊れているものを直す

目的：ユーザーに見えている欠陥をゼロに。「直す」だけで構造は変えない（安全・即効）。

対象作業検証（テスト = 仕様）
OG デフォルト画像 public/og-default.png を追加し PageHead.astro:25 と authors.ts:30 の参照先を修正 ビルド後の dist を走査し、og:image の全 URL が実在することを assert
親記事 OG 404 og/[...slug].png.ts を isParentPost() 述語に統一、/index 分岐を削除 「生成ファイル名 = BlogPost が要求する URL」を親・子の両方で固定
グラフのリーク モジュール変数で保持 + astro:before-swap で destroy() + in-flight fetch 中断フラグ destroy で worker/observer/rAF が解放されることをユニットで固定
TOCHeader リーク scroll ハンドラと observer をフィールド化し disconnectedCallback で解除 切断で removeEventListener / disconnect が呼ばれることを固定
ノードドラッグ無効 drag ハンドラを zoom より先に登録（空打ち時は drag が早期 return し pan は維持） 登録順の回帰テスト + subject 探索の純関数テスト
タグノード遷移 /blog?tag= → /tags/{tag}/ へ変更（encodeURIComponent 付き） クリック時の遷移先が実在ルートであることを固定
CI ゲート test:run スクリプト追加、CI に pnpm test:run を挿入 CI が緑（＝175 テストが初めて常時実行される）

PHASE 1 芯の一本化 — データ層の真実を 1 つに

目的：「同じ値を 2 箇所で計算しない」状態にする。OG 404 と TZ ズレの根本治療。既存テスト（posts/links）は良質なので活かす。

対象作業検証
ID 正規化 glob ローダーの generateId へ移動。posts / links / og / graph の replace() を全削除 フォルダ index・通常・サブ記事の ID スペックを先に書いてから移行
日付 dateKey/formatDate を唯一化（JST 固定）。groupPostsByYear・OG・ActivityGraph を置換 JST 深夜 0:00 と UTC 深夜の境界ケースを TZ 環境を変えて固定
親子判定 isParentPost() に集約（BlogPost・OG・SubpostsHeader・グラフ） 親 / 子 / 孫の 3 ケースをスペック化
draft 一貫性 getParentPost を getPostById 経由に統一（draft 親の漏れを防止） 「draft 親を持つ公開子記事」のケースを固定
リンク解析 (?<!!) ガードで画像を除外、inline code を除去 画像パスがバックリンク化しないスペック
並び順 同時刻時のタイブレーカーに localeCompare を追加 同時刻 2 記事の順序が決定的であることを固定

PHASE 2 ライフサイクルと性能 — 動き続けるものを制御する

目的：グラフと TOC を「賢く止まる」部品にする。CPU・バッテリー・メモリの消費を意図通りに。

対象作業検証
worker のリサイズ RESIZE メッセージを追加し center/x/y 力のターゲットを再計算 メッセージ受信で力の座標が更新されることを固定
アイドル停止 visibilitychange で非表示時に停止、prefers-reduced-motion で回転なし hidden / reduced-motion で tick が止まることを固定
死んだ config velocityDecay を worker に接続（意図値を確認）または削除。空グラフガード追加 config 値が実挙動に反映されることを固定
描画ホットループ closure 巻き上げ・ラベル幅キャッシュ・shadowBlur を hover/重要ノードのみに 純関数（座標変換・半径計算）のテスト + 目視確認
座標とヒット判定 ヒット半径をズーム係数 /k で補正、hover と drag の閾値を統一 拡大・縮小状態でのヒット判定を座標計算の純関数で固定
TOC 共通化 3 コンポーネントの observer / 折りたたみを observeActiveHeading() に集約 解放（before-swap）の対称性を 1 箇所でテスト

PHASE 3 研磨 — 重複を消し、死コードを削る

目的：読む人の負荷を最小化。「1 つの概念 = 1 つの実装」を全レイヤーで達成。

対象作業検証
共有スタイル / 部品 @utility card・PostMeta（著者+日付+読了+子記事数）・getSocialIcon()・pluralize() 既存コンポーネントテストを修正しつつ、出力 HTML の等価性を担保
死コード削除 Hero / SocialIcons / Badge テンプレート / getPostsByAuthor / isSubpostTitle / parentPost / isCurrentSubpost / colorClass / isBidirectional / light.grid / DESTROY / data-slot など約35箇所 各削除の前に「grep 参照ゼロ」を証明。テストからも同時に削除
死んだ CSS / 設定 chart・popover・accordion トークン、scheme-light-dark、tw-animate 系 class、Geist 未接続フォント、components.json、Vite external、Pagefind 二重索引 ビルド後 CSS サイズと dist 出力の変化を確認
Home / About Home.astro（262行）を分割し <header> 化・ICONS 使用。About の経歴データを consts へ外出し レンダリング HTML の構造テスト（header / h1 / データ件数）
a11y パック aria-current 修正・h1 追加・ul 直下修正・inert・JSON-LD エスケープ・<time datetime>・twitter meta 修正・reduced-motion 各項目をコンポーネントテストで固定（文字列ではなく属性で assert）

PHASE 4 門番 — 再発を許さない仕組み

目的：今回直したものが二度と壊れないようにする。ドキュメントを実態に同期し、テストを「本当の仕様書」に。

対象作業検証
真空テスト修復 アサーション 0 件・catch 内 expect・自己参照・mock 写しのテストを実データ + literal 期待値に書き直し 「わざと壊す → 赤くなる」を 1 つずつ確認（mutation 的な抜き取り検査）
純関数抽出 graph の座標変換・dedupe・category 割当を lib へ抽出してテスト。theme/検索は最小の DOM テスト manager / interaction に初のテストが付く
ドキュメント同期 README（v7・実アーキテクチャ・コマンド）と AGENT.md（.test.ts・コマンド・構成図）を実態合わせ 記載コマンドを CI で実行（乖離の機械検出）
型の強化 noUncheckedIndexedAccess 等を有効化、typecheck スクリプト追加、本番コードの as any ゼロ化 astro check が新しい制約下で緑
ビルド設定 CI の pnpm v10 統一（packageManager）、prettier check 追加、eslint ignores 漏れ修正 CI 緑 + ローカルとの lockfile ドリフトなし
