このプロジェクトの全体像

romophic.com は、数学・アルゴリズム・ソフトウェアの記事を公開する個人技術サイトです。 Astro で構築された完全静的サイト（SSG）で、実行時のデータベースもサーバー処理もありません。 記事を書くと、ページ・OG画像・検索索引・RSS・グラフデータがすべてビルド時に自動生成されます。 この文書は、その構造と仕組みを1枚の図にまとめた全体マップです。

37公開記事（親6 + サブ31）
50生成されるHTMLページ
239テスト（65ファイル / Vitest）
38OG画像（記事37 + default）
深掘り用のドキュメント: 動く仕組みは how-it-works.html、 改善の意思決定の記録は refactoring-plan.html にあります。

3 / しくみ

ソースからブラウザまでの4層

「ビルド時に全部やる」がこのサイトの中心思想です。上の層から下の層へ、一方向に変換されていきます。

L1 ソース

リポジトリの中身

記事（Markdown/MDX）と、それを表示するコードだけ。

src/content/blog 記事 src/pages ルート定義 src/components 35 個のUI部品 src/lib 記事解決・グラフ生成 src/styles デザイントークン
↓
L2 ビルド

pnpm build が全部作る

型検査から検索索引まで、1コマンド3ステップ。

1 astro check（型・テンプレート検証） 2 astro build（ページ・OG画像・sitemap・数式・コード） 3 Pagefind（検索索引の後処理）
↓
L3 成果物

dist/ には静的ファイルだけ

配信にサーバー処理は不要。このフォルダを置くだけでサイトが完成します。

HTML 50 OG PNG 38 graph.json 42ノード / 120リンク Pagefind 索引 37ページ フォント 124チャンク rss.xml ・ llms.txt ・ sitemap
↓
L4 実行時

ブラウザで起きること

動くコードはここだけ。それも外部通信なしで完結します（コメントを除く）。

ClientRouter（スムーズなページ遷移） テーマ切替（保存・FOUCなし） Ctrl+K 全文検索 知識グラフ（Web Worker + Canvas） Giscus コメント（iframe）
つまり実行時にサーバーが行う処理は ゼロ。表示が速く、壊れる箇所が少なく、どこにでも置けるのがこの構成の利点です。

4 / ページマップ

サイトはどんなページでできているか

人が見るページと、機械（RSSリーダー・LLM・SNS）が読むファイルを同じビルドで生成します。

  • / 記事の活動グラフと最新記事
  • /blog 記事一覧（ページネーション）
    • /blog/[id] 記事 37 親 6 + サブ 31 の2階層
  • /tags タグ一覧
    • /tags/[tag] タグ別の記事一覧
  • /about プロフィール
  • 機械が読むファイル （ユーティリティルート）
    • /rss.xml RSS 2.0（全37記事）
    • /llms.txt / /llms-full.txt LLM 向けの要約と全文
    • /graph.json 知識グラフのデータ（42ノード・120リンク）
    • /og/[slug].png SNSカード画像 38 枚
    • /robots.txt / /sitemap-index.xml クローラー向け
    • /pagefind/ 検索インデックス
    • /404 見つからないときのページ

5 / データの流れ

3つの代表的な流れ

記事を書いてから読者に届くまでの主要なパイプラインを、左から右へ。

記事の一生

content → pages → 派生出力
STEP 1記事を書くsrc/content/blog に MDX を追加
STEP 2解析・検証frontmatter を検証し、親子構造・読了時間・タグを計算
STEP 3ページ生成本文ページ・一覧・タグ・前後ナビをレンダリング
STEP 4派生出力OG画像・RSS・llms.txt・graph.json・検索索引を同時に生成

知識グラフ

graph.json → Worker → Canvas
STEP 1内部リンクを抽出全記事の本文から記事間リンクを収集
STEP 2graph.json に集約42ノード・120リンク。ビルド時に固定
STEP 3ブラウザで計算d3-force を Web Worker で実行し描画を止めない
STEP 4Canvas に描画ドラッグ・ズーム・クリックで記事へ移動

全文検索

build → Pagefind → Ctrl+K
STEP 1ビルド完了生成された全HTMLページ
STEP 2索引を作成Pagefind が日本語向け索引を生成（37ページ）
STEP 3dist/pagefind へ索引もただの静的ファイル
STEP 4Ctrl+K で検索ブラウザ内だけで完結（外部通信なし）

7 / 品質の守り方

テストは「生きた仕様書」

仕様はドキュメントではなく、実行できるテストとして書かれています。壊れた瞬間に気づける形が基本です。

239テスト（Vitest）
65テストファイル
0lint エラー（ESLint 10）
0型エラー（astro check）
GATE 1 pnpm lint コードの一貫性・危険な書き方を検出
GATE 2 pnpm test:run 239 件のテストで振る舞いを検証
GATE 3 pnpm build 型検査 → 本番ビルド → 検索索引まで通す
この3ゲートがすべて緑になることが「変更完了」の定義です。GitHub Actions（.github/workflows/ci.yml）が push のたびに同じ検査を自動実行します。

8 / 開発ワークフロー

日常的に使うコマンド

開発サーバーはバックグラウンド実行と stop/status/logs による管理に対応しています。

pnpm astro dev --background開発サーバーを起動（管理: astro dev stop | status | logs）
pnpm test:runテストを1回実行（239件）
pnpm lintESLint による静的解析
pnpm build型検査＋本番ビルド（Pagefind 索引まで）
pnpm astro preview --background本番ビルドをその場で確認
pnpm astro build --timingsビルド各工程の所要時間を計測
環境: Node 22.23.3（nvm-windows）／ pnpm 10.24 ／ 「新しい依存は原則追加しない」方針。 困ったときの詳細手順は AGENT.md にまとまっています。
